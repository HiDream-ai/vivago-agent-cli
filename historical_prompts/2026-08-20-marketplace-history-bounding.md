# Marketplace 安装分支历史控制

## 背景

公开插件把六个平台二进制放在安装分支中，以便 Codex 和 Claude Code 用户无需额外运行时即可安装。
当前单个快照的体积可以接受，但持续使用普通快进提交会让二进制历史随版本线性增长。

## 用户要求

- 优先控制安装分支的历史增长；
- 暂不减少当前自包含安装包的体积；
- 保持现有插件安装和运行方式。

## 已确认的决定

- 个人 Dev 和公司 Beta 安装分支都改为只保留当前版本的无父提交快照；
- 发布机器人读取准确远端 SHA，并使用精确 `force-with-lease` 更新，禁止无租约强推；
- Tag、Release、checksum、SBOM 和构建证明继续作为不可变版本档案；
- 事故恢复仍发布更高版本的安全替代包，不把安装通道指回旧问题版本；
- 先在个人开发通道验证连续发布、Codex 和 Claude Code 更新、并发冲突与回滚证据，再启用公司通道。

## 明确不做

- 不引入 Git LFS；
- 不改成首次运行下载单平台二进制；
- 不改变 CLI 登录、API、环境选择或用户数据；
- 不削弱 `main`、Tag 或 Release 的保护规则。
