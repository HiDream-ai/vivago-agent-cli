# Marketplace 安装分支历史控制

## 背景

公开插件把六个平台二进制放在安装分支中，以便 Codex 和 Claude Code 用户无需额外运行时即可安装。
当前单个快照的体积可以接受，但持续使用普通快进提交会让二进制历史随版本线性增长。

## 用户要求

- 优先控制安装分支的历史增长；
- 暂不减少当前自包含安装包的体积；
- 保持现有插件安装和运行方式。

## 已确认的决定

- 个人 Dev 和公司 Beta 安装分支都改为只保留当前版本的无父提交快照；
- 发布机器人读取准确远端 SHA，并使用精确 `force-with-lease` 更新，禁止无租约强推；
- Tag、Release、checksum、SBOM 和构建证明继续作为不可变版本档案；
- 事故恢复仍发布更高版本的安全替代包，不把安装通道指回旧问题版本；
- 先在个人开发通道验证连续发布、Codex 和 Claude Code 更新、并发冲突与回滚证据，再用下一个公司 Beta 实际验证同一机制。

## 实施结果

- 个人开发通道已经完成两个连续版本的快照更新，第二个版本通过六平台、双宿主 12/12 生命周期；
- 安装分支从 6 个可达提交降为 1 个无父提交，可达 Blob 约从 253 MB 降为 42 MB；
- 临时仓库推送无法继承调用仓库认证的问题已修复，并增加调用仓库 Git hook 回归测试；
- 同版本换源码的恢复尝试继续被不可变 Release 校验拒绝，没有放宽发布保护；
- 公司 `0.3.0-beta.2` 已使用同一脚本完成发布；六平台 6/6、双宿主 12/12、Release、checksum、SBOM 和两份构建证明全部通过；
- 公司 `marketplace` 在 `beta.1` 和 `beta.2` 后均为 1 个无父提交、33 个 Blob、42,418,915 字节，第二次发布增长为 0 字节；
- 本机隔离 Codex 使用真实 `beta.1`、`beta.2` Release 包完成安装、升级、回滚和再升级；
- `beta.2` 生产代表性冒烟通过附件识别、SSE 图片生成和产物 preview/download；短效 GitHub Environment Secret 已在运行后删除；
- 历史控制 PR 已进入公司 `main`，并同步到个人 GitHub 和 Codeup 的 `main`；
- 当前权限要求收窄为“外部普通用户不能向公司仓库推送或强推”，公司研发拥有写权限并可更新
  `marketplace`；
- GitHub 公开仓库的默认协作者权限已经满足该要求：外部用户和 Fork 只能读取公开产物，不能写回
  公司仓库，也拿不到公司 Actions Secret；
- 2026-08-20 只读复核显示，公司仓库拥有写权限的 outside collaborator 数量为 0；
- 不新增 Deploy Key、机器人账号或 Ruleset，`Publish Beta` 继续使用仓库 `GITHUB_TOKEN` 和精确
  `force-with-lease`；
- 如果后续需要限制公司研发直接更新安装分支，再作为独立治理需求设计，不阻断当前 Beta。

## 明确不做

- 不引入 Git LFS；
- 不改成首次运行下载单平台二进制；
- 不改变 CLI 登录、API、环境选择或用户数据；
- 不改变 `main`、Tag 或 Release 的现有权限；
- 不限制已经拥有公司仓库 Write/Admin 权限的研发更新 `marketplace`；
- 不新增发布凭据或执行权限演练。
