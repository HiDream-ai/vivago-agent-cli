# 标准环境代理兼容决策

## 背景

公开 Beta 用户的网络环境不同：部分用户可以直接访问海外正式环境，部分用户需要通过本地或企业代理
访问。现有普通 API 已兼容标准环境代理，但附件上传和产物下载为了强化 SSRF 防护而固定为直连。

## 用户需求

让普通 API、附件上传和产物下载采用一致的标准环境代理体验：用户配置代理时使用代理，没有配置时
直接连接，同时不能削弱上传和下载已有的目标地址及文件安全检查。

## 已接受决策

- 使用 Go 标准库 `http.ProxyFromEnvironment` 兼容 `HTTP_PROXY`、`HTTPS_PROXY` 和 `NO_PROXY`；
- 不增加 Vivago 专用代理参数或配置文件；
- 区分业务目标和用户配置的代理地址，允许本地代理位于 loopback 或私网地址；
- 直连路径保留按已校验公网 IP 拨号；代理路径在连接代理前校验业务目标 URL 和公网 DNS；
- 保留上传重定向禁用，以及下载域名、重定向、类型、大小和原子落盘限制；
- 不在直连失败后自动切换代理或重新上传；
- 代理配置、代理凭证和预签名 URL不得进入日志、机器输出或仓库。
- CLI 只遵循标准环境代理变量，不管理 Clash 等第三方代理软件的节点、TUN 或分流规则；如果特定代理
  错误处理对象存储域名，应在用户网络侧做精确规则调整，不能把该规则固化到公开插件。
- 本机生产验证已证明：精确调整对象存储分流后，附件上传、SSE、图片生成、预览和下载可以完成；
  这不替代六平台 CI，也不把本机代理配置视为产品依赖。

## 明确非目标

- 第一版不自动读取系统代理、PAC 或第三方代理软件配置；
- 不保存代理地址或代理认证信息；
- 不处理企业自签 CA 安装；
- 不改变海外开发与海外生产的编译时 Profile 边界；
- 不引入 Hosted MCP 或标准 OAuth。
